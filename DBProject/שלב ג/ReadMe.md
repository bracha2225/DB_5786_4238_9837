## שלב ג': אינטגרציית בסיסי הנתונים (שיטה ב' משופרת - Cross-Schema)

### 1. שחזור, הנדוס לאחור (Reverse Engineering) וניתוח המערכת שנתקבלה
קיבלנו את גיבוי בסיס הנתונים של הקבוצה המקבילה (מערכת ניהול סגל - Staff). שחזרנו את הנתונים לתוך סכמה נפרדת בשם `staff_schema` כדי לשמור על סדר ומניעת התנגשויות.

* **שלב א' - הפקת תרשים DSD:** מתוך הטבלאות שקיבלנו, מיפינו את המפתחות הראשיים והזרים ובנינו את תרשים ה-DSD של האגף החדש.

<img width="1488" height="749" alt="dsd other" src="https://github.com/user-attachments/assets/bab9689e-56ca-40c5-99d3-9da5e34b0159" />

* **שלב ב' - אלגוריתם הנדוס לאחור (Reverse Engineering):** כדי להגיע לתרשים ה-ERD, הפעלנו אלגוריתם שבוחן את המפתחות הזרים (Foreign Keys):
  1. כל טבלה רגילה הופכת לישות (Entity).
  2. שדות ייחודיים הופכים לתכונות (Attributes).
  3. עמודה שהיא מפתח זר (FK) מעידה על קשר (Relationship) מסוג $1:N$ עם הטבלה שאליה היא מצביעה.
  4. טבלת קישור שכל המפתח שלה מורכב משני מפתחות זרים מעידה על קשר מסוג $N:M$.
  * **שלב ג' - הפקת תרשים ERD:** באמצעות האלגוריתם, שרטטנו ב-ERDPlus את תרשים ה-ERD המקורי של האגף שקיבלנו.

### 2. עיצוב ERD משולב (Integration at Design Level)
בשלב זה, כאשר בידינו שני תרשימי ה-ERD (שלנו ושל האגף החדש), ביצענו את תהליך האינטגרציה ברמת העיצוב בתוכנת ERDPlus.

**החלטת עיצוב:** הגדרנו קשר חדש בשם `AttendedBy` מסוג **One-to-Many ($1:N$)** המחבר בין ישות המטופלים (`patient`) שלנו לישות אנשי הצוות (`staff`) שלהם. החלטה זו נובעת מההיגיון העסקי שכל מטופל משויך לאיש צוות רפואי אחד (רופא אחראי/מנהל מקרה), בעוד שאיש סגל יכול לטפל במטופלים רבים.

### 3. תרשים DSD לאחר אינטגרציה (Logical Schema)
מתוך ה-ERD המשולב, גזרנו את הסכמה הלוגית החדשה (DSD). בתרשים זה, טבלת `patient` (שנמצאת בסכמה `public`) כוללת כעת שדה מפתח זר חדש בשם `StaffID` המצביע ישירות על טבלת `staff` (שנמצאת בסכמה `staff_schema`).


### 4. אינטגרציה פיזית בבסיס הנתונים (Integrate.sql)
לאחר הגדרת המבנה הלוגי והתכנון התיאורטי, ביצענו את שלב האינטגרציה הפיזית בשרת ה-PostgreSQL בתוך בסיס הנתונים `basnat`. לפי הנחיות המרצה (שיטה ב' משופרת), שתי המערכות המקוריות נשמרות ופועלות במקביל תחת אותו שרת אך מופרדות באופן לוגי באמצעות סכמות נפרדות: הסכמה שלנו נקראת `patients` והסכמה שקיבלנו נקראת `staffschema`.

ארכיטקטורה זו מאפשרת לנו לבצע קישור ישיר ויציב בעזרת מפתחות זרים טבעיים (Native Foreign Keys) המבטיחים תקינות נתונים מלאה וביצועים מקסימליים, ללא צורך במנגנונים מורכבים כמו Foreign Data Wrappers.

כדי לבצע את הקישור מבלי למחוק או לייצר מחדש את הטבלאות מאפס, הרצנו פקודות DDL לעדכון המבנה הקיים. יצרנו את קובץ ה-SQL בשם `Integrate.sql` המכיל את הפקודות הבאות:

#### 4.1 שיוך אוטומטי וחלוקת נתונים (Data Distribution Algorithm)
כדי שלא להשאיר את השדה `staffid` כ-`null` וכדי לבצע אינטגרציה אמיתית בין הנתונים שלנו לנתונים שקיבלנו מהגיבוי, כתבנו והרצנו שאילתת `UPDATE` חכמה המבוססת על אלגוריתם חלוקה שוויונית (Round-Robin). 

השאילתה משתמשת בפונקציית חלון `ROW_NUMBER()` ובפעולת `MOD` (שארית חלוקה) כדי לשייך באופן אוטומטי ומאוזן כל מטופל מהסכמה שלנו לאיש סגל מהסכמה שקיבלנו, מבלי להזין נתונים ידנית:

### 5.1 מבט 1: נקודת מבט אגף מטופלים (view_patient_medical_assignments)

#### תיאור מילולי
מבט זה מציג את פרטי המטופלים יחד עם פרטי איש הסגל הרפואי המשויך אליהם באמצעות קשר LEFT JOIN בין סכמת המטופלים לסכמת אנשי הסגל.


<img width="752" height="422" alt="4" src="https://github.com/user-attachments/assets/e4a7e495-7f38-46ce-9559-ba4a746de73c" />

##### שאילתה 1.1: שליפת כל המטופלים שמטופלים על ידי אנשי צוות פעילים במערכת
* **תיאור מילולי:** שאילתה זו מסננת את פלט המבט ומציגה רק את המטופלים שמשויכים כרגע לאנשי סגל שסטטוס העבודה שלהם הוא פעיל ('Active').
* **קוד השאילתה:**
```sql
SELECT * FROM patients.view_patient_medical_assignments 
WHERE staff_status = 'Active';

##### שאילתה 1.2: ספירת כמות המטופלים הצעירים שיש להם איש צוות רפואי משויך
* **תיאור מילולי:** שאילתה המבצעת אגרגציה (ספירה) של כל המטופלים שנולדו משנת 2000 ואילך, ועבורם קיים שיוך תקין ולא ריק לאיש סגל רפואי כלשהו במערכת.
* **קוד השאילתה:**
```sql
SELECT COUNT(*) AS young_patients_with_staff
FROM patients.view_patient_medical_assignments
WHERE date_of_birth > '2000-01-01' AND staffid IS NOT NULL;
```

### 5.2 מבט 2: נקודת מבט אגף סגל (view_staff_workload)

#### תיאור מילולי
מבט זה נוצר בסכמת הסגל ומציג את סיכום עומס העבודה עבור כל איש סגל. המבט משתמש בפונקציית אגרגציה (COUNT) ובקבוצה (GROUP BY) כדי לחשב במדויק את כמות המטופלים המשויכים לכל איש צוות.
<img width="780" height="512" alt="5" src="https://github.com/user-attachments/assets/739911dc-0e4e-422e-bb9e-4578ff6ff8da" />

##### שאילתה 2.1: הצגת אנשי סגל שיש להם עומס עבודה גבוה
* **תיאור מילולי:** שאילתה השולפת מתוך המבט רק את אנשי הצוות הרפואי שמטפלים ביותר מ-5 מטופלים במקביל, לצורך מעקב וניהול עומסים במרפאה.
* **קוד השאילתה:**
```sql
SELECT staffid, firstname, lastname, total_assigned_patients
FROM staffschema.view_staff_workload
WHERE total_assigned_patients > 5;
```

##### שאילתה 2.2: חישוב הממוצע הכולל של מטופלים המשויכים לאיש סגל
* **תיאור מילולי:** שאילתה המחשבת את ממוצע המטופלים המשויכים לכל עובד רפואי מתוך המבט שהוקם, לצורך אופטימיזציה של כוח אדם במערכת.
* **קוד השאילתה:**
```sql
SELECT AVG(total_assigned_patients) AS average_patients_per_staff
FROM staffschema.view_staff_workload;
```
